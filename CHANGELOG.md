# Changelog

Dated entries, newest first. Each entry groups changes as Added, Changed, Fixed and Decisions.

## 2026-10-23 (win)

### Edit tools (TL1)
- Added: four arrange tools, Split, Glue, Erase and Mute (`Tool::Split|Glue|Erase|Mute`, ids `split`, `glue`, `erase`, `mute`, aliases `cut` and `eraser`; `Tool::ALL` is 11). Click a clip: Split cuts it at the pointer, Glue joins it to the clip that starts where it ends (1 sample tolerance, otherwise the status line says there is nothing to glue), Erase deletes it, Mute toggles its mute. Erase and Mute also work by dragging across clips (the swept clips get a pending tint and one command runs on release; Mute applies the first clip's new state to all). Each is one undo step, locked clips are refused with a status message, and none changes the selection. In an automation lane view they only grab breakpoints, like the Grabber.
- Added: engine command `clip.split {clip | clips, at}` (undoable; splits only the named clips, not every clip on their tracks; refuses locked clips and a position outside every named clip) on a new `separate_clips_at` helper. `edit.tool` lists the new ids.
- Added: right-click menus of clips and empty lanes start with a Tools submenu (Object Select, Range Select, Split, Glue, Erase, Zoom, Mute, Draw, Scrub, Trim, Smart) with an icon, a check mark on the active tool and the key of the active key set (F-key when the set has none); the Edit menu has the same submenu. Ctrl (Cmd on macOS) with right-click on a lane opens a compact tool palette (4 by 3 icon grid, tooltips with keys, Escape or a click outside closes it) instead of the menu, without changing the selection.
- Added: toolbar buttons for the four tools after Draw in both toolbar styles (the Standard tools group is 11 keys wide); tooltips show the key of the active key set. Icons `mute` and `erase` drawn in code (`split` and `glue` already existed).
- Added: Alternative key set 3 split, 4 glue, 5 erase, 7 mute (labels "Edit Tool: Split" and so on); the Default set is unchanged and has no key for them.
- Added: cursors for the new tools (crosshair with a guide line at the cut point, alias, not-allowed, pointing hand) and a small glyph of the tool next to the pointer.
- Decisions: Ctrl/Cmd swaps the Split snap (the existing drag convention) and Shift makes Split also cut the selected clips under that time, instead of Shift bypassing the snap. Glue restores the previous clip selection afterwards, so the tools never select. Documented the Smart tool definition and the key table in `docs/ui-parity.md`.

### Clipboard keys on a real keyboard (KF1)
- Fixed: Cmd/Ctrl+X, C and V did nothing on a real keyboard, because the platform sends Cut, Copy and Paste events instead of key events. They are now turned into the same chords (unless the key event also arrived), so the roll, the arrange window, user key overrides and both key sets work as before; text fields keep the native events.
- Fixed: Paste events only arrive when the system clipboard holds text, so an internal copy or cut now leaves a short marker text there. The internal clipboard stays the source of truth; foreign clipboard text is ignored.

### Cut, copy and paste (CP1)
- Added: piano roll clipboard. `midi.notes_copy`, `midi.notes_cut`, `midi.notes_paste`, `midi.notes_duplicate` (`crates/engine/src/cmd/midi_clip.rs`) with a note clipboard (`Clipboard.notes`) kept apart from the arrange clipboard. Notes keep mute flags, controller events under the notes (on the shown lanes) travel with them, paste goes to a given tick, else the position last placed in the roll, else the playhead or insertion point inside the clip, else the clip start; the clip grows to hold the notes and the pasted notes become the selection. One undo step each. Works across clips, tracks and after the editor is closed.
- Added: keys over the piano roll or its controller lanes: Cmd/Ctrl+X, C, V, D (and A) act on the notes in both key sets and are not sent to the arrange window; anywhere else they cut, copy, paste and duplicate clips as before. The roll's right-click menu has Cut, Copy, Paste (at the clicked tick) and Duplicate with the Edit key text and enabled states; a controller lane's menu has Cut Events, Copy Events and Paste.
- Fixed: Paste with several clipboard tracks onto fewer selected tracks lost the extra tracks; they now continue downward from the first target. A clip no longer lands on a track of the other kind (MIDI on audio, audio on MIDI), the paste is refused with the reason. Pasting an empty clipboard is an error, not an undo step. Pasted clips are selected; cutting clears the stale clip selection. Cutting selected clips takes exactly those clips, not other clips that overlap their range. (Copied clip settings such as scale already follow pasted clips from the earlier batch.)
- Decisions: the roll owns the chords only while the pointer is over it (like its arrow keys), no focus memory; the note clipboard stores positions relative to the first event, no grid offset; right-click Paste in the roll lands at the clicked tick, the key at the placed position or playhead; the controller events travel with the notes only for controller lanes that are shown. This replaces the earlier decision that the roll has no note clipboard.

### Remaining items, engine and model batch (RM1 B1)
- Added: `automation.to_clip` and `automation.merge_into_clip` (`crates/engine/src/cmd/auto_convert.rs`): a controller lane (CC, pitch bend, channel pressure) of an instrument or MIDI track becomes controller events in the MIDI clips under a range, or in one named clip. Switch lanes write held values; continuous lanes are sampled every 32nd note and thinned with a one-pass filter to within half a controller step. A clip is created when none is under the range. Locked lanes, audio tracks and non-controller parameters are refused. One undo step each.
- Added: `file.export_midi` takes `lanes` (default false) to write MIDI controller lanes as controller events in the file. Clip controller events were already exported; this only adds the lanes.
- Added: `track.midi_params` (and the query `track.midi_params_get`): transpose (-48..48), velocity offset and a channel override per instrument or MIDI track. Stored in the session's numeric settings (transpose and velocity are the same values `event.midi_rtp` sets, the channel is `midi.channel.<track>`), so no session field was added and old sessions load unchanged. The mix engine sends the override on notes (through new `Plugin::note_on_ch` and `note_off_ch`, honoured by CLAP in MIDI mode) and on controllers.
- Fixed: a note that started before a transpose or channel change was released at the new pitch and stayed on. The mix engine now releases held notes with the values they started with when either changes, and only sends a note-off for a note it holds.
- Fixed: live (audition) notes and their timeout no longer send note-offs to an instrument that failed to load.
- Added: `options.audition_tail_ms` (default 300, 0 to 2000): the release tail of an auditioned note. It was a fixed 1.5 s; the default is now shorter.
- Added: `Session::reid_clip` and `Session::copy_clip_meta`: copies, pastes, track and playlist duplicates and the right half of a split now keep a clip's scale, which lives in the numeric settings keyed by clip id (`CLIP_META_KEYS`). Before, a copy lost the scale.
- Tests: lane to clip (ramp thinning, round trip against the lane, held switch values, pitch bend range, replace-in-range, refusals, one undo step, channel override, export with and without lanes); `track.midi_params` clamps, refusals, undo; audition tail command; mix engine tests for note release on a transpose change, matching note-offs, channel override, no settings; failed instrument gets no note-off; tail length follows the setting; split halves and pasted copies keep the scale.
- Decisions: the plan assumed MIDI track transpose and velocity did not exist and needed model fields; they already exist as real-time properties, so `track.midi_params` is a typed, undoable front end to the same values plus the new channel setting, with no model change. The plan placed the new-clip helper in the clip module; it needs the numeric settings, so it is on the session. The command channel in the playback crate carries a plain enum and not boxed closures, so there is nothing to send back; the rare frees on the audio thread are listed in the gaps document and left. There is no per-note probability field, so no probability lane; recorded as later in the gaps document. The two template folders (per-user, then beside the executable) are kept and documented. The new commands have no menu entry yet and are listed as known unreached in the reachability test until the UI batch names them. Not verified on macOS: the channel override on Audio Unit note input (not implemented there), and everything touched by `cfg(target_os)` is unchanged.

### Arrange context menus and an alternative key-command preset (CK1)
- Added: right-click menus built from the command catalogue (`context_menu.rs`). Each line's label, key text and enabled state come from the command registry and follow the active key set, a disabled line says why on hover, and a click runs the command like its key (through its dialog when it has one). Surfaces: clips (cut, copy, paste, delete, split at playhead, split range, glue, duplicate, repeat, mute, unmute, edit lock, time lock, Fades and Process submenus, quantize, loop, unloop, group, ungroup, bring to front, send to back, colour, rename, open editor for MIDI clips, render clip gain, bounce), empty lanes (paste, select all, select none, locators to selection, add marker, add track), the ruler (add marker, locate here, set left or right locator here, loop on/off, zoom to selection, zoom to fit), the track header and the mixer strip body (mute, solo, record enable, select all clips on the track, then the existing items), the piano roll (delete, split, glue, mute, quantize, transpose, velocity, select all) and controller lanes (clear, remove). A right-click on a clip selects it first unless it is already selected; on an empty lane it selects that track.
- Changed: right-clicking a controller lane no longer clears it, and right-clicking a lane label no longer removes the lane, both silently; the lane's menu offers Clear Lane and Remove Lane (the label's own drop-down keeps only its hover text).
- Added: engine commands `clip.glue` (selected audio clips must be contiguous parts of one file with equal gain, otherwise an error that names the clips and suggests Consolidate, nothing rendered; MIDI clips merge into one clip, muted or locked clips refuse), `clip.mute` and `clip.unmute` (explicit, idempotent), `edit.delete` (removes the selected clips without closing the gap and skips locked ones; with no clip selected it behaves like Clear), `edit.split_at_playhead`, `transport.locate_left` and `transport.locate_right`, `transport.set_left_locator` and `transport.set_right_locator`, `edit.locators_to_selection`, `track.select_prev` and `track.select_next`, `clip.select_prev` and `clip.select_next`. None has a Default-preset key.
- Added: key sets. The command registry's keys are the "Default" set and are unchanged. A new UI-layer overlay (`keymap.rs`) adds the "Alternative" set: single-letter commands (M mute, S solo, R record enable, C click, Q quantize, H and G zoom, P locators to selection), number-row tools (1 object select, 2 range select, 6 zoom, 8 draw, 9 scrub), Delete and Backspace, Insert for markers, arrow keys for previous and next clip and track, Alt+X split at playhead, Shift+X split range, Alt+G glue, Cmd+K repeat, Cmd+Y redo, Enter play, 0 stop, `/` loop, `.` or Home return to zero. Commands the set does not list keep their Default key unless the set uses that key. Letters, digits and arrows never fire while a text field has the keyboard.
- Added: Settings > Keys. Key set drop-down, search, a table of every command with its keys as chips (click a chip to remove it), Assign (captures the next key press; Escape cancels), a conflict message naming the command that holds the key with Reassign or Cancel, per-row Reset and Reset all. Per-command keys work on top of either set, several per command, for commands with fixed parameters too (tools, nudge). Keyboard Shortcuts now lists the active keys and links to the page.
- Added: `ui.prefs` takes `keymap_preset`, `keymap_overrides`, `keymap_reassign` and `keymap_reset` and reports `keymap_preset` and `keymap_overrides`; they are saved in the UI preferences (see docs/control-protocol.md). Bad chords, unknown commands and taken chords are errors that change nothing; saved keys for unknown commands or broken chords are dropped at load.
- Fixed: `clip.loop` and `edit.move_selection_left` both claimed Cmd+Alt+L, so Loop was unreachable by key; Loop is now Cmd+Alt+Shift+L. A new test requires every parseable default key to belong to one command (the Space trio and the Mix/Edit trio are the only allowed repeats).
- Tests: engine tests for glue (contiguous, gap, other file position, MIDI), mute idempotence, delete, split at playhead, locators and neighbour selection, all with undo; `keymap_alt.rs` (Alt+X, Cmd+K, M, Shift+M, `/`, number-row tools, Delete, Ctrl+Y, Default unaffected, no letters in text fields, user keys on the Default set); `settings_keys.rs`; `context_menus.rs` (one test per surface); preference round trip and load clean-up in `settings_cmds.rs`. The clip menu test now finds its Delete line by label instead of by pixel position.
- Decisions: the window toolkit reports numeric-keypad keys as their main-row twins (digits, `/`, `.`, Enter), so keypad-only transport keys are not possible; the Alternative set uses plain keys for transport, and tools use the number row. `edit.separate` with no range already splits at the insertion point but ignores the playing position, so `edit.split_at_playhead` is a separate command that uses the playhead (the position while playing, else the insertion point). `edit.timeline_to_selection` goes the other way (it copies the loop range to the edit selection), so `edit.locators_to_selection` is new. `edit.tab` only moves the insertion point, so previous/next clip selection is new. The piano roll has no note clipboard, so its menu has no cut, copy or paste; Process lists Normalize, Reverse and Invert only (Gain needs a value dialog). Not verified on macOS: Cmd and Ctrl mapping of the Alternative keys, native menu key text, Option-key chords.

Loop playback and play-from-selection read only the locators, so they do nothing special for a clip selection. Command ids are unchanged.
- Added: the shipped theme "Night Owl" (`themes/night-owl.json`, canonical form).
- Tests: `new_session_stops_playback_and_the_old_clock` asserted a position above 48000 only because the demo cursor used to sit at bar 4; it now asserts the clock runs (position above 0). Clip select leaves the selection untouched and cut/copy of a selected clip work with an empty range; a non-empty range wins over selected clips; no loop band after selecting a clip.

### Themes in the repository and a shared themes folder
- Added: a top-level `themes/` folder of theme files that ships with the app. Its themes are embedded at build time (desktop and web), listed read-only as "Shipped", and can be loaded or duplicated; `themes/slate.json` is the first one. `cargo xtask themes` checks them (valid file, file name is the slug of the name, LF, canonical text, plain names) and is part of `cargo xtask ci`; `.gitattributes` keeps them LF.
- Added: a shared themes folder (Settings > Appearance "Shared folder": Choose..., Use detected, Off). The desktop app finds the `themes/` folder of the source checkout it was built from, only when it runs from a cargo build folder, never for an installed app and never under `SOUNDCRAFT_NO_PREFS`. The choice is the `shared_themes_folder` UI preference. Themes saved there can be committed to git and show up on the other machine after a pull.
- Added: theme scopes (built-in, shipped, shared, this computer, not saved) with a badge in the list and next to the picker, a "Save to" selector (This computer or Shared folder; the choice is the `theme_default_scope` preference) and a "Move to shared folder" button. Commands: `ui.theme_move`, `ui.theme_folder`; `scope` on save, load, duplicate, import, rename and delete; `ui.theme_list` reports scope, read-only state, folders, preferences state and skipped files; `ui.theme_get` reports `scope`.
- Changed: theme files are canonical and named `<slug>.json` (lowercase, dashes), keys sorted, unset settings left out, LF and a trailing newline; saving twice gives identical bytes, so git diffs only show real changes. Old `<Name>.json` files still load and are replaced by the slug file on their next save, never duplicated.
- Changed: folder scans accept only valid theme files of at most 256 KiB (UTF-8 JSON of our format, usable name, one file per name); anything else is skipped, listed in `ui.theme_list` and shown as a warning line on the Appearance page. A newer file version still loads.
- Fixed (N1): saving a theme with no folder to write to (preferences off, tests, web) no longer looks like it worked. The command succeeds with `saved_to: "memory"` and a warning, the page shows it in the warning colour and keeps the Name box, the list marks the theme "Not saved", and the page shows a banner "Preferences are off for this run: themes are not saved". A failed write to the shared or user folder is an error naming the folder; nothing is silently redirected.
- Tests: canonical bytes and slug cases; folder scan with malformed, foreign, oversized, non-UTF-8, over-long-name, newer-version, temporary and hidden files; shipped themes parse, are canonical and resolve without warnings; scopes, collisions, legacy files, move, shipped read-only, memory and unwritable-folder cases in `theme_editor.rs`; the Appearance page (banner, folder row, Save to, Move, shipped buttons, kept name) in `settings_theme_folders.rs`; folder detection in `apps/soundcraft`.
- Decisions: the product-name word list cannot live in a committed file, so the committed test `shipped_theme_names_are_generic` and `cargo xtask themes` check the shape of names (short plain words, no links) and the local check-names script scans `themes/`. One theme file per theme; shared and shipped copies of a name are never merged (the shared one hides the shipped one). Not verified on macOS: the exe path detection for Mac builds, the native folder dialog, Mac write failures, a Mac/Windows checkout round trip through git.

- Inspector: the dock panel now has collapsible sections (header with inline rename, colour swatch and mute/solo/record/monitor buttons; Routing; Instrument; Inserts with an "Add EQ" button; Sends; Channel with fader, pan, trim and meter; Notes) for the selected track, shown by track kind. Clips without their own colour already follow the track. New tracks still cycle through the 16-colour set (and any palette override).
- Glossy rounded clips and track headers: clip bodies, clip name bars, header colour strips and the Mix strip name chip get a soft vertical gradient, a top highlight and rounded corners. New theme tokens `clip_gloss` (0 flat, 1 full; Dark 1.0, Light 0.8, Midnight 0.6), `clip_corner` and `header_corner`, with a "Glossy clips" switch and a "Corner radius" slider in Settings > Appearance. - Inspector redesign: a glossy track-colour header band (large editable name, type badge, clickable colour chip, mute/solo/record/monitor toggles with state colours), collapsible rounded section cards (Routing, Instrument, Inserts, Sends, Channel, Notes) with count pills, insert rows with a bypass LED and hover actions, "+ Add effect" and "+ Add send" rows, a "+" and a "..." section menu for the extra insert actions, and a compact Channel card (fader, meters, pan, trim, phase). - Mixer pane strips are now stacked: name chip, input/record/solo/mute row, pan, then the fader with meter and dB readout, with inserts, sends and routing folding into count badges, then an output row, then full lists as the pane gets taller. The Master strip is fully visible at the default height.
- Selected clips keep their outline when muted, dimmed or shown under an automation view, and the outline is drawn above the name bar; the gloss gradient no longer shows outside rounded corners.
- Settings > Appearance: colour rows sit in an aligned four-column grid and show the full hex value.

### Decisions
- A one-pixel dashed line that differed between two Light-theme screenshots was the blinking insertion cursor on the selected track, not a header width effect; the stored default header width and the built-in default give bit-identical widths (test added). Screenshot comparisons must account for the cursor blink phase.
- Plans are stored in `plans/`, which upstream ignores.
- The fork keeps new behaviour in new files with tiny hooks into existing files.
- Clicking in the piano roll must not change the session (upstream test), so the play-from position is editor state.
- A per-note mute field was not added to `Note` (about 35 literal construction sites in 18 files); note mute is implemented as a side table on the sequence instead (see below).
- Rust toolchain updated to 1.99.1 with clippy and rustfmt.
- Test processes sometimes exit with STATUS_ACCESS_VIOLATION after all tests pass (upstream, uninvestigated).
- The floating MIDI editor is an in-app floating panel drawn inside the main window, not a separate OS window.
- Panel header controls cannot change the dock layout while the dock is drawing, so they queue a request that the dock applies right after the frame.
- `midi.audition` is declared with the journaling no-undo kind like other transport commands, so the command-reachability test applies; it is listed as a temporary known gap in `command_reachability.rs` until the piano-roll audition UI names it, and the test then forces the line's removal.
- Live notes are separate from clip-scheduled notes (a per-strip table of 128 timeout counters) and are not given the track's real-time transpose or velocity offsets yet.
- The Audition queue drops events when full (256); the engine's 2 s timeout covers a lost release.
- The `Audition` toggle is a user preference (`UiState.audition`, default on, old preferences load unchanged); the sounding note lives in editor state.
- At that point the default floating MIDI editor width became 1040 pt (was 960) so the new Audition group still fit with every other header group (historical; the current value is 1460 pt, clamped to the window).
- Existing test `a_real_pointer_drag_up_100_points_grows_the_lane_by_about_100` became `..._80_points_..._80`: with the corrected lane maximum the test panel cannot grow the lane by 100 pt; the intent (drag distance equals growth) is unchanged. `lane_height_clamps...` expects 472 instead of 480 for the same reason. `midi.audition` was removed from the command-reachability known gaps (the UI now references it).
- Panel hint strips take their space from the dock area (the dock gets the remaining rectangle) rather than overlaying content; their clicks queue a dock request like the other panel buttons. The right-click menu is offered on tabs, tab-strip buttons and the hint strips; the Session canvas itself keeps its own right-click behaviour.
- Window menu entries reuse the existing window toggle commands (which sync through the dock) instead of adding a parallel set; only `window.show_all_panels` is new.
- The piano roll snap is the editor's own (default "Grid" follows the session edit grid, so nothing changes until the user picks another value); it never writes the session grid.
- Info strip edits go through one new command, `midi.notes_adjust`, instead of `midi.note_edit` plus `midi.notes_move`: the sequence re-sorts after every edit, so several index-based calls would act on the wrong notes, and one command is one undo step.
- Test changes (upstream tests adapted, not weakened): `tests/midi_panel.rs` now clicks `roll.top() + 22` instead of `body.top() + 60` (the same place inside the roll; the info strip and taller ruler moved the roll down), and the lane-drag test drags 40 pt instead of 80 because the extra chrome leaves 42 pt of lane growth in the 320 pt panel (the 120 pt roll minimum is unchanged); the in-file header layout test lists the new groups and the default floating width constant moved to 1380.
- Editor snap, strength and note-colour state are not saved between launches yet (the colour switch is a session view flag); persisting them is left for the editor-state work.
- Add Multiple... opens the existing New Tracks dialog, which appends at the end (it does not know the clicked track).
- Mute is a side table on the sequence, remapped by `Sequence::sort_tracked`, `retain_notes`, `remove_duplicates`, split, glue, adjust and clip split/trim; consolidating MIDI drops muted notes (they are silent).
- Existing tests adjusted: `midi.lane_h` became `midi.lanes[0].height` (same behaviour); the header layout test now includes the Inspector item and the clip label needs 1700 pt instead of 1600 (also in tests/midi_panel.rs).
- Lane minimum height stays 40 pt (plan said 24) to keep the V1 clamp rules; lanes, tool, snap and inspector state are not persisted between launches.
- Scale root/kind stored as one number per clip in `edit.values`; no model change.
- Recovery dialog investigation: after one unclean exit (taskkill) the app offers that one autosave; Discard removes it and the dialog does not return (reproduced in the real app). The reviewer saw a changing "autosaved N ago" because several autosave folders from earlier killed runs were present and the dialog offers them one at a time. Expected behaviour, no code change.
- A clip's scale (`edit.values` key `midi.scale.<clip>`) is not carried to copies or splits: new clips are created at about 59 call sites with no common helper, so a safe single fix is not possible. Left as a known gap.
- Midnight clips use fill opacity 112 of 255 (168 selected) so the bar and beat grid shows through them while the waveform stays readable; Dark and Light stay opaque. Test change: `tests/grid_lines.rs` now loops over three themes (added Midnight); nothing weakened.
- Compact is the default header (user request); existing upstream tests that click the classic header by position (`edit_window.rs` unit tests, `tests/edit_window_headers.rs`, `tests/folder_ui.rs`) now select Classic first in their harness. Nothing was weakened; the compact header has its own tests in `tests/track_header_compact.rs`.
- The compact header uses the Mix fader law (`fader_db_to_pos`) for its slider and the same merge key (`fader:<track>`) as the Mix faders, so a drag in either place is one undo step. The edit button opens the plugin window; it does not add a new editor.
- Existing tests adjusted for the new default layout: the Edit window drag-scroll test harness sets the transport to Top (its geometry assumed the old bottom edge), and the Mix name-plate right-click test subtracts the bar height from its y position. Nothing else was weakened.
- Showing and hiding a lane are undoable edits; switching a lane's parameter, locking, following and resizing are view commands (no undo step, no dirty flag). A lane that follows a knob must not split the undo step of the knob's own gesture: any non-view document change ends a merged gesture.
- Follow detects a touched parameter by comparing parameter values each frame (only for tracks that show lanes) instead of hooking each editor: automation playback does not change the session values, so a change means the user (or a command, or undo) moved it. Instrument slot edits from hosted editors are not reported by the editor bridge and are not followed.
- The value readout sets the fixed parameter value through the existing mix commands; it does not write breakpoints.
- T16b: the bar's Float, gear and close keys are part of the right zone; the float key is the last optional item to go, gear and close never go. The secondary readout defaults to Timecode because the main counter defaults to Min:Secs. The floating bar is an egui window whose size state is keyed by `transport_float_gen`, so a command that places it starts it fresh; the window is drawn only in the root viewport. Closing the bar (x) needs View > Transport > Show transport bar (or `ui.transport_visible`) to bring it back; no keyboard shortcut was added because none was clearly free.
- T16b-5: `Panel::Master` joins `Panel::ALL`, the panel list (`panel_menu::LIST`, now six entries), the Window panel commands and the dock limits; it belongs to the Edit window only (the Mix window has its master strip). Test expectations changed on purpose: `panel_discovery.rs` (labels list and the check-mark id list now include Master / `window.master_panel`), `theme_docking.rs` (opens `window.master_panel` too), and the `panel_menu` unit test (six panels in Edit). `docking_workflows.rs` needed no change. Saved layouts without the Master panel still load (test: legacy preferences). The existing pills Memory Locations and Undo History stay in the left strip.
- H1: the minimum column width is 112 pt for the compact header and 136 pt for the classic one; the maximum is 640 pt or 45 percent of the canvas width, re-applied each frame while the saved value stays. `edit_window::header_width` now takes the base width as a parameter; `HEADER_W` stays as the default constant.
- The transport bar tests that clicked fixed offsets (`tests/transport_bar.rs`) now find the keys through the pure layout, because the keys moved to the centre.
- `command_reachability.rs`: `options.pre_roll` and `options.post_roll` left KNOWN_UNREACHED because the transport bar's gear menu now sets them (the test itself demands that).
- Work runs in batches: an executor builds several planned tasks in a row, then one full format, lint and test run and one independent review cover the final state of the batch. Intermediate commits are not built and tested separately.
- Review per batch: the reviewer checks every task of the batch against its plan, runs the full checks and real-app checks, and records a pass or fix-needed verdict per task; fixes go to a fix pass before the batch is committed.
- Commits are made locally after each batch and pushed only after the user has reviewed them.
- Branch model: `custom-release` is the integration branch (it replaced the old `custom` branch, same history; the old branch was deleted); `custom-windows` and `custom-mac` hold the work of each machine and merge into `custom-release` after their checks; `main` mirrors upstream.
- Two repositories: planning notes, status logs and references live in a separate private notes repository cloned as the ignored `plans/` folder; this repository holds only code and generic docs. `docs/DEV-HANDOFF.md` describes how both are pushed and pulled together when work moves between machines.
- The free disk space query lives behind a service hook so the UI crate stays free of platform file-system dependencies; only the desktop app crate depends on `fs4`.
- Settings window: no Editing page in v1 (per-session edit flags stay in the Options menu); auto-update window configuration is not saved; the page layout is a sidebar so Audio or Editing pages can be added later.
- Settings window commands follow AGENTS.md: UI-only commands are rows in `menus.rs` `UI_COMMANDS` with their handlers in a new file; the Window menu entry is renamed by editing the catalog line, and the menu item for Setup > Preferences... still runs `setup.preferences` before opening the window so the command stays reachable from the UI.
- (mac) The Standard menus and toolbar are the default and Classic stays selectable: the menus are a presentation layer over the same command catalog, so command paths, the parity floor and tests are unchanged in both layouts.
- (mac) View-state commands are registered as `view` (not journaled, not undoable, not stored in the session: layout, toolbar style, palette override, panel visibility) or `noundo` (journaled but not undoable: `edit.grid_adaptive` is a session flag, and `template.new_session` replaces the document like `session.new`). `view` commands also need no menu path in the command reachability test. The split keeps the undo history to document edits while a replayed journal still reproduces the document.
- (mac) The Mac work reached the release branch by fast-forward (tag rel-2026-10-22), so the promotion is the same history as the Mac branch; the Windows branch merges the release branch and rebuilds before continuing.
